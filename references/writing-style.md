# 用语表达与文风规范

## 1. 总体文风

采用正式、克制、可执行的技术文风。句子应说明对象、动作和结果，不依靠宣传性形容词制造专业感。

- 使用客观陈述，避免口语化的“我们认为”“其实”“非常”“比较好”。
- 保留原稿的判断强度，不把可能性写成确定性，也不把建议写成强制要求。
- 优先使用具体对象和动作，少用“全面赋能”“深度融合”“行业领先”“彻底解决”等无边界表达。
- 一段集中处理一个逻辑单元。背景、问题、方法、成果和指标不要无提示地混在一起。
- 句子通常控制在 2 至 4 个动作内。连续并列过多时拆句，不用一个超长句覆盖完整技术路线。
- 同一术语保持一致。首次使用原稿中的全称，后续使用原稿已有简称。
- 中文标点采用全角；英文、型号、单位和公式保留原有写法，不改变数值含义。
- 标题编号只保留一套前缀和后缀。默认使用 `一、`、`二、` 或 `六、` 这类形式；不要把序号再包成“第六章”，也不要生成“第六、”“六章、”等混合写法。来源已有标题时先尊重来源，用户要求去除冗余包装时只改编号外壳，不改标题正文。

## 2. 去 AI 味采用改写而不是删减

- 默认目标是降低模板腔和宣传腔，不是缩写、摘要或提炼全文。
- 对“立足、坚持、突出、赋能、打造、构建新范式”等表达，先识别其承载的视角、原则、目的或作用，再改写成客观陈述；不得直接删除整句。
- 对概括性的影响判断和价值判断，即使没有数字，也要保留。例如“这些问题相互影响，制约管理能力提升”可改为“上述问题共同影响管理能力提升”，不能整句删除。
- 对推荐后的作用说明，应保留原稿已有的自主性、灵活性、扩展性或其他判断，只调整措辞，不得只留下推荐结论。
- 拆分长句时允许增加句子和段落数量。不得为了显得简洁而把多个并列观点合并成一个泛化结论。
- 只有逐项比对确认语义完全重合时才能去重；无法确认时保留并改写。

改写示例：

| 原表达 | 保留式改写 |
| --- | --- |
| 立足顶层设计、坚持系统思维、突出价值牵引，推动平台建设 | 平台建设从总体架构、系统协同和应用价值三个方面组织实施 |
| 这些问题相互交织、彼此影响，制约了管理能力的进一步提升 | 上述问题共同影响管理能力提升 |
| 这一选择有助于形成更加自主、灵活和可持续的平台能力 | 该方案有助于增强平台的自主性、灵活性和持续扩展能力 |

## 3. 技术动词的使用边界

| 动词 | 适用对象 | 表达目的 |
| --- | --- | --- |
| 分析、梳理 | 现状、需求、流程、影响因素 | 明确输入和问题边界 |
| 研究 | 机理、方法、算法、关键技术 | 描述尚需攻关的内容 |
| 提出 | 方法、策略、技术路线 | 表达新的解决思路 |
| 构建 | 模型、体系、架构、知识库 | 表达多要素组织成整体 |
| 建立 | 机制、规则、映射关系、指标体系 | 表达约束或关联关系 |
| 研发、开发 | 平台、模块、系统、工具、算法实现 | 表达可交付的软件或工程实现 |
| 集成 | 已有模块、数据、接口、系统 | 表达组合与互联 |
| 形成 | 技术、方法、标准、成果、能力 | 表达阶段性产出 |
| 实现 | 功能、状态、效果、指标 | 表达最终能力或结果 |
| 验证 | 方法、模型、平台、指标 | 表达试验或应用检验 |

不得只为模仿样本文风而堆叠这些动词。每个动词必须有明确宾语，且宾语必须来自原稿。

## 4. 科研材料的句法组织

科研材料可使用下列信息顺序，但不要求每段机械套用同一句式：

`针对场景与问题 → 明确研究对象 → 说明研究方法 → 构建模型或体系 → 形成成果 → 实现原稿已有目标或指标`

推荐的拆句方式：

1. 第一句界定应用场景、对象和问题；
2. 第二句说明拟研究、构建或开发的内容；
3. 第三句说明集成、验证、成果或应用效果。

当原稿没有成果、效果或指标时，停在已有信息处，不补齐句式。

## 5. 决策方案的表达方式

- 背景说明回答“为什么现在需要决策”；
- 痛点说明回答“现状造成什么业务影响”；
- 对比项使用相同评价口径，先写事实，再写适配性判断；
- 优势和局限必须来自原稿，不转换为新的结论；
- 推荐段先陈述既定结论，再组织原稿已有依据；
- 实施建议按阶段、任务、责任或依赖关系组织，不新增时间和资源承诺。

避免把决策方案写成科研申报语气。除非原稿确实描述研发活动，否则不滥用“研究、创新点、技术攻关”。

## 6. 需求清单的表达方式

- 一条需求只表达一个可响应事项；
- 使用“支持、实现、提供、满足、具备”等能力型动词；
- 条件、动作、对象和结果尽量在同一条内完整出现；
- 供应商响应项保持可核对，不改写成宣传文案或研究目标；
- 不把已有需求扩展为新功能，不根据表格类别推导额外识别项。

## 7. 段落编辑检查

每次改写后在内部核对：

- 主语或责任主体是否仍与原稿一致；
- 数字、方向词、程度词和结论是否完整保留；
- 句子是否增加了原稿没有的因果关系；
- 同一内容是否因改写被重复计算或重复承诺；
- 技术动作与成果对象是否匹配；
- 是否出现过度模板化的连续句式。
- 原段落中的每项观点、理由、作用和判断是否都能在改写后定位；
- 是否把“去 AI 味”误做成了摘要或大幅缩写。
