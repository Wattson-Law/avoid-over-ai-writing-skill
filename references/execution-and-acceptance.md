# 执行与验收规范

本文件是每次规范化 Word 成稿任务的必读执行门槛，适用于 DOCX、Markdown 文件及粘贴文本入口。所有检查结果只用于内部修复，不写入文档，也不向用户生成问题清单。

## 1. 解析运行能力

- 使用目标环境实际具备的 DOCX 结构编辑和页面渲染能力。WorkBuddy、Codex 或其他宿主均可使用自身已提供的文档 API、Python/Node 库、Word 自动化或 LibreOffice。
- 本 skill 不依赖 Codex 专用 `documents` skill。该能力存在时可以使用，不存在时直接采用目标环境的等价能力，不得因此跳过正文处理、格式验收或逐页渲染。
- 通用格式验收器已随 skill 内置 `python-docx` 和 `typing_extensions`，目标 Python 只需提供原生 `lxml`。若当前解释器缺少 `lxml`，验收器会返回 `validator_runtime` 失败；应改用宿主中已具备 `lxml` 的 Python 或等价结构验收能力，不得把依赖失败当作验收通过，也不得未经用户授权在线安装依赖。
- 始终从输入另存输出副本。编辑器必须能保留图片、表格合并关系、字段、分节、页眉页脚及业务文本；渲染器必须能输出文档的全部页面供目视检查。
- 若当前环境无法编辑或无法渲染，不得把未经完整验收的文件描述为已完成。

## 2. 锁定处理强度

- 未收到用户的明确强度指令时，锁定为 `editorial`。运行中不得静默改成 `format-only`。
- `editorial` 要逐段判断并执行保留式写作处理：消除机械铺陈和口号式句法，修正病句与搭配，统一原稿已有术语，梳理句内逻辑，同时保留全部语义单元与受保护信息。
- 建立仅供内部使用的“源段落—输出段落”映射，并标记文字处理动作。已经符合目标文风的段落可以不改，但不能用“无需修改”覆盖整篇正文以规避写作处理。
- 若输出中所有可编辑正文与源文档文字完全一致，先按 [writing-style.md](writing-style.md) 检查源稿是否仍含明确需要处理的宣传化、模板化或机械铺陈表达。只要存在任一此类表达，就判定 `editorial` 未执行，必须重新完成保留式写作处理；不得以样式变化代替文字处理，也不得仅更换标点来制造已改写的假象。只有整篇正文已经符合目标文风，且内部逐段映射记录为“无需改写”时，才允许文字保持不变。
- 文字处理后仍执行内容守恒审计。表达改进不能以降低事实、观点或表格内容保留度为代价。

## 3. 清除冲突的直接格式

Word 的直接格式优先于样式。仅套用目标样式不足以保证视觉结果，必须先处理受控区域中的冲突属性。

1. 识别封面标题、各级标题、表题、页眉页脚、业务表标题行、普通表格单元格，以及科研固定表单中的封面/签章/审核/布局结构表等受控区域。结构表不虚构列标题行，也不参与业务表题编号。
2. 清除这些区域中覆盖目标规范的段落与字符直接格式，例如旧字体、字号、颜色、底纹、对齐、缩进、段前段后、行距、分页控制及表格边框设置。
3. 再应用目标段落/字符样式，并在需要时明确写入规范要求的值。表格转为白底后，逐个文字 run 确认其自身或有效字符样式解析为明确黑色 `000000`；不能只清除单元格底纹而保留白字，也不能保留“自动”颜色或主题颜色。科研固定表单、签章区和仅承担页面布局的结构表以对应模式规范为先，只定点清除与目标规范明确冲突的直接格式，不得批量清空其合并关系、尺寸、对齐、留白或其他功能性布局。
4. 保留有业务或文档功能含义的结构与字符属性，如超链接、字段代码、书签、上下标以及原稿明确使用的局部强调。若这些属性与目标样式冲突，只调整冲突项，不删除其功能结构。
5. 保存后重新读取 DOCX 结构，确认没有遗留的直接格式继续覆盖标题、表题或表格规范。

## 4. 规范分页与分节

- 修改前盘点手动分页符、`pageBreakBefore`、分节符类型以及仅承载分页的空段落。
- 每个页面转换点只保留一种必要机制。`下一页` 分节符前后不得再保留作用相同的手动分页符、段前分页或空白分页段落。
- 新增或替换分节符时，先删除其相邻的冗余分页控制；不要把分页符与分节符连续叠加。
- 不删除用于章节分页且没有被分节符替代的必要分页，也不改变横向页、不同页眉页脚等依赖分节的结构。
- 由重复分页控制产生的空白页必须消除。只有源稿明确承载业务版式或用户明确要求保留的空白页才可存在。

## 5. 硬性验收门槛

按以下顺序执行；任何修改都会使后续结果失效，因此修复后必须从第一项重新开始：

1. 完成最终分页后先更新全部 Word 字段并保存。Markdown 输入还需核对原文到未改写 Word 基线的解析完整性。运行 `audit_content_preservation.py`，核对受保护内容、表格业务数据、正文保留率和内部语义映射。
2. 运行通用格式验收器：

   ```powershell
   & $PYTHON_BIN "$SKILL_DIR\scripts\validate_standardized_docx.py" `
     $OUTPUT_DOCX --mode $MODE --source $INPUT_DOCX `
     --processing-strength $STRENGTH `
     --report "$QA_DIR\format-validation.json"
   ```

   `$MODE` 取 `requirements-list`、`decision-proposal`、`rd-application` 或 `rd-implementation-outline`。命令必须以零状态退出，报告不得包含失败项。不得忽略、降级或人工豁免失败项后交付。
   只有用户在当前任务中明确要求保留彩色正文时，才可追加 `--allow-colored-text`。输入文件原有颜色不构成使用依据；该选项不豁免表格的白底黑字、黑色边框和黑色表头文字要求。
3. 对要求目录的文档，确认更新后的目录不是静态文本，`TOC` 字段覆盖一级至三级标题，已经生成可见目录项，点状引导线和页码完整；目录首页无可见页眉页脚，目录所在节从 1 计页，单页目录后的正文第一页显示 2，多页目录则按实际页数接续；标题文字、标题层级或分页发生变化后必须重新更新字段。
4. 将 DOCX 的每一页渲染为图像并逐页检查。页数以渲染结果为准，不得只检查包含表格的页面或随机抽样。
5. 逐页确认目录层级和页码与正文一致，且没有非业务所需的空白页、隐藏白字、旧配色、裁切、重叠、异常换行、孤立标题、页码越界或表格断裂；逐表确认表题连续、白底黑字和 `0.5 pt` 等宽黑色网格线。

失败信息和 JSON 报告只用于内部定位与修复，不转写为正文、批注、审查意见或用户可见的问题清单。内容审计、格式验收和全页视觉检查全部通过后，才能交付干净的规范化 DOCX。
