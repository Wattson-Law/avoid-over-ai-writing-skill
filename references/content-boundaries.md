# 内容保护边界

本文件是所有模式的强制约束。目标是改善文档的表达、结构呈现和格式，不评价或接管原作者的业务责任。

## 1. 必须原样保护的信息

编辑前建立内部内容守恒表，记录以下信息及其上下文：

- 项目、单位、部门、人员、厂商、平台、产品和系统名称；
- 日期、周期、阶段、数量、金额、比例、尺寸、面积、容量、时延、精度、准确率和其他数值；
- `不低于`、`不高于`、`不少于`、`不超过`、`至少`、`至多`、`≥`、`≤`、`±` 等指标方向；
- 业务范围、适用场景、责任主体、协作关系和交付范围；
- 方案结论、推荐顺序、优先级、优劣势判断和不推荐结论；
- 背景判断、建设必要性、问题影响、原因与结果、目标定位、能力描述、价值作用、推荐依据和实施意图；
- 表达中的限定、程度和强调作用。即使某句话看似概括、宣传或模板化，只要承载独立观点，就必须保留其含义；
- 表格中的全部业务数据、备注、空值含义和合并关系；
- 已有政策名称、标准名称、案例名称和引用信息。

允许统一数字与单位之间的空格、全半角符号和中文标点，但不得改变值、方向或含义。

## 2. 允许的编辑

- 修正不影响事实的语病、搭配不当、重复表达和指代不清；
- 统一同一对象在文档中的称谓，但首次全称和后续简称必须来自原稿；
- 拆分超长句，合并语义残缺的短句；
- 调整段内信息顺序，使背景、问题、措施、成果和效果更容易识别；
- 把空泛或宣传式句法改成客观、具体的陈述，但原句承载的定位、目的、作用和判断必须有对应表达；
- 在不改变结论的前提下增加过渡语，但过渡语不得包含新的事实判断；
- 按选定模式调整标题、编号、段落、表格、分页、目录、页眉页脚和样式；
- `restructure` 模式下重排已有段落或章节，但不能删除未被重复覆盖的信息。

## 3. 禁止的编辑

- 不核验、不纠正或替换疑似错误的事实、数字、指标方向和逻辑关系；
- 不生成问题清单、风险清单、审查意见、数据质量说明或修改建议；
- 不使用模板正文、通用知识或网络信息补齐原稿；
- 不新增政策依据、行业案例、技术路线、算法、参数、预算、人员、里程碑或量化指标；
- 不因编辑者认为某方案更优而改变推荐结论；
- 不把“可”“建议”“拟”“应”等程度或责任词相互替换，除非上下文明确只是语序调整；
- 不删除看似重复但承担不同阶段、对象或责任范围的信息；
- 不以“AI 味重”“像套话”“不够具体”为理由删除整句或整段；
- 不把多个不同观点压缩成一个概括句。只有两处表达语义完全相同，且后者没有新增对象、范围、程度、条件、原因、结果或强调作用时，才可合并；
- 不在交付文档或最终回复中输出内部内容守恒表。

## 4. 冲突和可疑内容的处理

遇到事实冲突、逻辑矛盾、指标方向可疑或前后表述不一致时：

1. 保留原稿各处的原始值、方向和结论；
2. 只优化句法、段落和格式，不选择其中一个版本；
3. 不添加“待确认”“疑似错误”“建议核实”等标记；
4. 不向用户单独输出问题清单；
5. 继续完成其余可执行的规范化工作。

只有用户明确要求核验或纠错时，才可切换到独立的审查任务；该任务不属于本 skill 的默认能力。

## 5. 内部验收

交付前至少完成以下只读比对：

- 源文档和输出文档的受保护数值与方向词多重集合一致；
- 表格业务文本和数据一致；
- 单位、主体、产品名称、结论和推荐顺序未改变；
- 原稿图片、图题和业务字段未意外丢失；
- 输出没有从参考资产带入项目专属文本。
- 原稿每个非重复语义单元都能映射到输出中的具体句子或表格单元格；
- `editorial` 模式的正文净字符保留率默认不低于 85%。该比例只用于识别过度删减，不能替代语义映射检查。

发现差异时只在内部修复，不向用户生成额外交付物。
