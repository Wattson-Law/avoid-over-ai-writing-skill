# 模式：科技研发项目实施大纲

## 适用范围

适用于项目获批后形成的实施大纲或执行方案。该模式强调工作包、实施方法、验证、进度、分工和预算，不把立项申请书的审核意见等栏目强加到实施大纲。

## 固定结构

输入有固定表单时保持其栏目和附件顺序。常见章节为：

1. 项目的研究意义及必要性；
2. 国内外研究概况及可行性分析；
3. 项目研发目标及主要内容；
4. 研究开发方法及技术路线；
5. 项目考核目标；
6. 项目进度计划；
7. 申报单位和协作单位及分工；
8. 项目经费预算。

实施方案内部优先按任务或工作包组织已有内容：任务名称、输入/对象、研究或实施步骤、集成关系、验证/应用、对应成果。原稿没有的环节直接省略。

## 页面与封面

- 保留并更新输入已有的自动目录；输入没有目录时不因套用本模式自行新增，只有用户在当前任务中明确要求生成目录时才按 [toc-generation.md](toc-generation.md) 在封面后、正文前新增；
- 正文 A4 纵向，上/下 1.00 英寸、左/右 1.25 英寸；
- 宽人员表、经费明细表和设备表可使用独立 A4 横向分节，上/下 1.25 英寸、左/右 1.00 英寸；
- 封面主标题使用方正小标宋简体，26 pt，加粗、黑色，居中；
- 封面单位名称约 18 pt、加粗、黑色、居中；项目字段使用 14 pt 仿宋；
- 输入模板含独立封面落款日期且原设计为加粗时，日期保持加粗、黑色；不得把项目起止年限等普通项目字段误判为封面日期；
- 保留项目编号、项目名称、申报单位、依托平台、协作单位、负责人、经费和起止年限的原有字段与顺序；
- 封面不添加页码。正文页码保持连续、居中且不使用容易裁切的窄浮动文本框。
- 新建横向分节时，横向表前、表后各使用所需的一个分节符，并移除同一位置已有的手动分页符或“段前分页”；不得叠加“分页符 + 下一页分节符”。除非固定模板明确要求奇数页/偶数页起始，分节一律不用奇数页/偶数页类型；横向内容结束后恢复纵向页面设置。
- 保留承载固定表单、附件、页眉页脚或页面设置的必要分节，只清除重复分页控制和纯占位空段；最终分页不得出现由连续分节符、连续分页符或二者叠加形成的空白页。

## 标题与正文

| 角色 | 规范 |
| --- | --- |
| 一级章节 | 仿宋_GB2312，16 pt，加粗，黑色，左对齐，段前/段后 12 pt |
| 二级标题 | 仿宋，14 pt，加粗，黑色，左对齐，段前/段后约 6 pt |
| 三级和工作包标题 | 仿宋，14 pt，加粗，黑色，左对齐，1.5 倍行距 |
| 正文 | 仿宋 + Times New Roman，14 pt，常规，黑色 |
| 正文段落 | 首行缩进 28 pt，1.5 倍行距，段前/段后 0，孤行控制 |
| 图题 | 宋体或仿宋，12 pt，黑色，居中，保留原有编号与文字 |
| 表题 | 宋体或仿宋，12 pt，黑色，居中，仅使用 `表1`、`表2`…… |

标题与下段同页；长工作包可自然跨页，但不要让编号标题单独留在页底。除非用户在当前任务中明确要求保留彩色文字，封面、标题、正文、图题、表题和表格文字的每个 run 本身或其有效字符样式必须解析为明确黑色 `000000`；输入文件原有颜色本身不构成保留依据。不得使用“自动”颜色或主题颜色。

仅对表格外、被识别为独立标题的段落清除影响目标样式的原稿直接格式，包括字体、字号、加粗、颜色、主题色、突出显示及段落缩进，再显式重设对应字体、字号、加粗、黑色、行距和段间距。一级至三级及工作包标题不得首行缩进或悬挂缩进，必须启用“与下段同页”；固定表单的单元格标签、附件表头、签章区和空白填写区不得套用标题样式或被清空直接格式。

## 表格与图示

- 使用黑白细网格表，不套用蓝色业务表；
- 每张业务内容表上方添加居中的独立表题，按出现顺序仅写 `表1`、`表2`……，不根据成果、进度、人员、预算或设备等内容自行拟题；仅用于封面字段排列、签字盖章、审核意见、附件标识或页面布局的结构表不参与表题编号；
- 表格统一白底、黑字，外框和内部网格均使用 `0.5 pt` 黑色实线，不加粗外框；
- 从有色表头改为白底时，必须同时逐 run 将列标题文字重设为黑色 `000000`，并清除其主题色、色调和阴影属性；不得只移除单元格填充而保留白字或主题色；
- 成果表、进度表、人员表、预算表和设备表保留原字段、合并关系、空白填写区及备注；
- 具有真实列标题行的业务表将该行加粗、水平/垂直居中并在跨页时重复；结构表不得把第一行误判为列标题或强制重复；表体根据字段类型居中或左对齐；
- 表格字体使用仿宋，按密度统一在 10.5 至 14 pt，不低于保证可读性的最小值；
- 16 列人员表等宽表优先横向分节，跨页时重复列标题行；
- 技术路线、系统架构、流程、设备布置和公式保持原图片或对象，不将图片内容臆写成正文；
- 不为减少页数压缩图片到不可读尺寸。

## 表达重点

- “研究意义及必要性”保留政策、行业和工程场景的递进关系；
- “可行性”集中组织原稿已有团队、经验、平台、数据或工程基础；
- “目标/创新点/研究内容”使用一致的任务名称和编号；
- “实施方案”将已有方法拆成可执行步骤，但不新增方法或承诺；
- “考核/进度/分工/预算”与原任务对应，所有值、方向、主体和金额原样保留。
